# Migration plan — feature/gameplay-updates

Этот файл документирует текущий план по поэтапному переносу и рефакторингу оригинальной страницы game1_v1_4.html в модульную структуру.

Цель
- Перенести игровую логику и SVG из большого монолитного HTML в аккуратно организованные файлы (game.js, styles.css, lib/...), при этом не ломая текущую механику игры.
- Устранить потенциально опасные практики (выполнение внешних скриптов с других origin, eval и т.п.).

Текущее состояние
- Ветка: feature/gameplay-updates
- index.html: локальная оболочка — безопасно загружает <body> из game1_v1_4.html и выполняет внутренние скрипты последовательно; подключает game.js.
- game.js: модульный bootstrap с настройками (localStorage), UI-контролами, hex-grid генератором, интеграцией с оригинальным #board и возможностью блокировать клавиатуру.
- PULL_REQUEST_TEMPLATE.md: шаблон для PR.
- Стартовый баланс оставлен 0.

Приоритетные задачи (по порядку)
1. Найти и извлечь все inline-скрипты и функции из game1_v1_4.html — классифицировать по ответственности: рендер поля, обработчики ввода, логика столкновений/удара, логика ходов, сетевые вызовы/внешние ресурсы.
2. Переместить код в модули:
   - src/board.js — генерация/обновление hex-board, API для выделения/подсветки тайлов
   - src/ui.js — элементы интерфейса (панели, кнопки, поповеры)
   - src/game-state.js — модель игры: игроки, корабли, ресурсы, ходы
   - game.js — точка входа: инициализация, координация модулей
3. Заменить исполнение inline-кода через eval на безопасную загрузку/инициализацию (через DOM <script> или импорт модулей при переходе на сборку).
4. Синхронизировать существующие SVG элементы (#board) с новым API (add event listeners, map shapes to tile coords).
5. Тестирование: локальное тестирование ключевых сценариев (ход, атака, покупка топлива, интеграция board).
6. Очистка: удалить старые, ненужные inline-скрипты и внешние ссылки, обновить index.html, README и документацию.

Мелкие задачи/улучшения
- Исправить подключение веб-шрифтов: заменить некорректный `@import` в HTML на <link rel="stylesheet"> или вынести в styles.css.
- Прописать CI (например, gh-pages или GitHub Actions) для локального предосмотра.
- Добавить unit/behaviour tests (по мере возможности) для core logic (pathfinding, damage calc).
